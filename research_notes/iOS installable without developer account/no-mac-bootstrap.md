# Bootstrapping iOS installs with ZERO computer access (no Mac, no PC, ever)

Research date: 2026-11-16. Scenario correction: the owner has **no computer at all** — one iPhone (EU/CZ), free burner Apple ID, GitHub Actions only. Supersedes the "one-time Mac setup" assumption in [channels-and-limits.md](channels-and-limits.md) (Q5/Q6) and [live-workflow-examples.md](live-workflow-examples.md). OTA/hosting mechanics, free-tier limits, and tool landscape are already covered there — cited without re-research. Labels: **[documented]** (primary docs/source), **[community]** (issues/blogs/videos), **[inference]**.

## Q1. SideStore bootstrap with zero computers

### iLoader verdict — a computer tool, but any OS
- **[documented]** iLoader is a **desktop** Tauri app (Windows/macOS/Linux), USB-connected, needing usbmuxd/iTunes — [nab138/iloader](https://github.com/nab138/iloader). SideStore's official install docs list **only** iLoader-on-a-computer ([docs.sidestore.io/docs/installation/install](https://docs.sidestore.io/docs/installation/install), fetched 2026-11-16). The old plan was wrong twice: not Mac-specific (any computer), and not computer-free. With zero computers, iLoader is unusable directly.

### Apple's Oct 2026 auth waves (-80045/-80046) — current status
- **[community]** Timeline ([Ixion blog, 2026-10-24/30](https://blog.illixion.com/2026/10/sideloading-error-80046)): **Oct 12** — Apple rejects sign-ins whose claimed platform doesn't match the anisette (→ **-80045**; SideStore [#1658](https://github.com/SideStore/SideStore/issues/1658), [#1665](https://github.com/SideStore/SideStore/issues/1665), [discussion #1651](https://github.com/orgs/SideStore/discussions/1651)). **Oct 22** — Apple refuses the `com.apple.gs.xcode.auth` token to requests claiming Android (→ **-80046**). **Oct 30** — the 403/503 wave traced to Apple's edge blocking `Content-Type: text/x-xml-plist`; `text/xml` works.
- **[community]** Fix state Nov 2026: **iloader 2.4.0/2.4.1** fixed (jkcoxson's Mac anisette + own `ani.iloader.app`); xtool 1.23+, atvloadly 0.7.4+, iPASide 1.2.9+ fixed; **SideStore has no release fix** (still 0.7.0-alpha, Sept 2026) — users get in via anisette overrides/jkcoxson server, "often only after several tries"; AltStore 2.3.1 (Oct 21) "Fixed error -80045" — [AltStore release notes](https://faq.altstore.io/release-notes/altstore). Community-verified Nov 4 recipe: "iLoader 2.4.0+ → install SideStore (Nightly) standalone; don't use the LiveContainer+SideStore bundle" ([#1658 comment](https://github.com/SideStore/SideStore/issues/1658#issuecomment)). **Bottom line: the bootstrap leg still works in Nov 2026, but SideStore's own sign-in is the flaky part — expect anisette fiddling and use a burner ID.**

### Every zero-computer bootstrap path (stock iPhone)
1. **SideInstaller + siboot — the real no-computer path.** **[documented]** [FrizzleM/SideInstaller](https://github.com/FrizzleM/SideInstaller) v2.0.1 (1.4k★): "Install SideStore and LiveContainer directly on your iPhone. No PC required." Fully no-PC bootstrapping via [siboot](https://github.com/FrizzleM/siboot) requires **iOS 27+**: three free App Store apps (**rootshell**, **Open Minis**, **LocalDevVPN**) → `siboot-pair.wasm` in rootshell's local shell → "Pair with siboot" in Developer Mode → install script in Open Minis → SideInstaller, "signed with your own Apple account: no computer and no certificate" → it installs SideStore with your Apple ID. **iOS 26.4–26.7 needs a PC-made remote-pairing file; 17.4–26.3 a PC-made lockdown pairing file** (README compat table) — the no-PC path is gated on iOS 27; older phones can update if eligible. Risks: trust chain is one pseudonymous dev's builds from [sideinstaller.net](https://sideinstaller.net/) — the README warns forks "can insert a credential stealer" and that **sideinstaller.com is a fake/malware site** **[documented]**; the rootshell mechanism (App Store app providing a local shell + pairing) is killable by Apple in any release **[inference]**; walkthroughs exist ([Oct 2026 video incl. -80045 fix](https://www.youtube.com/watch?v=YmRi1JJG3zc)) **[community]**; no independent audit — **unverified** how rootshell achieves pairing.
2. **Legacy: enterprise-cert one-time bootstrap.** **[documented]** SideInstaller offers "install SideInstaller with one of the enterprise certificates at sideinstaller.net/#legacy" for pre-iOS-27 devices. **[community]** Enterprise certs are revocation-prone ([scarletios.com comparison](https://scarletios.com/free-sideloading-tools-compared-2026-edition) — promotional source), but as a one-time step acceptable per the owner: revocation kills only the bootstrap app, not the SideStore re-signed with your own free ID. Only from the official site; never mirrors.
3. **Apparition** (illixion, open source) — on-device sideloader for iPhone/iPad/Vision Pro/Apple TV, free Apple ID, self-refresh, JIT; 0.4.3 (Oct 30) has the auth fixes — [apparition.illixion.com](https://apparition.illixion.com). **Unverified:** its iPhone first-install path ("desktop apps… for the first install") — likely needs bootstrap tooling itself.
4. **eSign forks / Feather / KSign** — BYO-cert on-device signers; original eSign discontinued 2025, forks of mixed provenance ([channels-and-limits.md](channels-and-limits.md) Q5). Chicken-and-egg unless obtained via enterprise-cert OTA; gray-market risk without added capability.
5. **Scarlet-style shared-enterprise-cert stores** — no setup, but revocation kills everything signed with it and it never becomes self-sustaining under your own ID. One-time step only.
6. **Not viable:** AltStore Classic 2.3 "Remote AltServer" removes the computer for *installs/refresh* but the *first* install still needs AltServer on a computer ([release notes](https://faq.altstore.io/release-notes/altstore)); TrollStore dead on current iOS; PAL — see Q6.

## Q2. On-device minting for `com.therapylocal.app`
- **[documented]** SideStore's core function: "SideStore resigns apps with your personal development certificate" using your Apple ID on-device — [SideStore FAQ](https://docs.sidestore.io/docs/faq). Free-account limits: **3 apps installed at once (SideStore counts as one), 10 App IDs/week**, 7-day profiles (same FAQ; Apple limits in [channels-and-limits.md](channels-and-limits.md) Q1).
- **Bundle ID kept.** **[documented-by-behavior]** FAQ: "Your apps shouldn't need any modification to work with SideStore!" — no ID mangling for non-App-Store IDs (mangling only where the ID collides with an App Store app — [Sideloadly FAQ](https://sideloadly.io/faq), per [channels-and-limits.md](channels-and-limits.md)). AltStore 2.3.1 added **opt-in, experimental** "Randomize Bundle IDs" — AltStore-only; no SideStore equivalent found (searched 2026-11-16 — **unverified** none exists). **[inference]** `com.therapylocal.app` is preserved; one-time check that it's not an App Store bundle ID.
- **Slot count for us:** SideStore (1) + Therapy app (1) = **2 of 3 slots**; **2 of 10 weekly App IDs** in week one, re-used thereafter. **[documented]** Our build has no extensions (`.github/workflows/ios.yml` packs `MindVault.app` only, no `.appex`), and SideStore 0.6.2 added "reuse the main App ID profile for extensions… (only one app id/app)" ([release notes](https://docs.sidestore.io/docs/release-notes)) — extensions wouldn't blow the budget either.

## Q3. p12 export from an on-device mint → CI
- **Export exists.** **[documented]** SideStore 0.6.2: "importing/exporting your Apple ID's certificate" ([PR #1008](https://github.com/SideStore/SideStore/pull/1008)), plus "url scheme/allow exporting certificate (to LiveContainer)"; issue [#65](https://github.com/SideStore/SideStore/issues/65) closed as completed 2026-07-16. **[community]** UI: Settings → Certificate Management → long-press certificate → Export .p12 — [r/SideStore](https://www.reddit.com/r/SideStore/comments/1vfadsq/is_it_possible_to_export_the_signing_certificate); SideInstaller consumes it via the `sidestore://certificate` callback (SideInstaller README).
- **But it doesn't unlock CI.** **[community]** SideStore's export is **p12-only** — "it doesn't export the mobileprovision file so the .p12 alone is useless" ([#65 comment](https://github.com/SideStore/SideStore/issues/65)); the LiveContainer trick drops `.p12` + `.mobileprovision` into Files, but that profile is LiveContainer's own, not ours. **[inference]** Kill shot: a free-team profile for `com.therapylocal.app` is minted only in the device flow and dies in 7 days; no maintained 2025–2026 tool mints free-team profiles headlessly (SignTools-CI dropped free accounts — [live-workflow-examples.md](live-workflow-examples.md) Q1), and headless Apple-ID automation with 2FA relay is exactly what Apple's Oct 2026 waves attack, with account-lock risk. **Verdict: leg (b) (p12 → CI re-sign → one-tap itms OTA) is dead without a computer; CI could at most hold a p12 whose matching profile it cannot renew.**

## Q4. Cross-team adoption = vault data loss? — SETTLED: treat as YES
- **[documented]** SideStore FAQ "Can I transfer my AltStore/Sideloadly apps?": "Yes… sideload the same or an updated IPA… with your data still intact" — the same-tool, **same-Apple-ID** case.
- **[community]** Cross-team is different: iPASide changelog — "Re-signing an installed app with a different team's identity produces something iOS will not install over the existing copy" ([pwnapplehat/iPASide CHANGELOG](https://github.com/pwnapplehat/iPASide/blob/main/CHANGELOG.md)); MultiStore: "re-sideload over the existing app **with the same Apple ID** — don't delete it first — so your added accounts and app data are preserved" ([lungustefan/MultiStore](https://github.com/lungustefan/MultiStore)); Provenance wiki: exceeding limits means "install with a **different Apple ID and Bundle IDs**" ([wiki.provenance-emu.com](https://wiki.provenance-emu.com/getting-started/installing-provenance/advanced/sideloading)). **No Apple primary doc** states the rule — mechanism is community-reported with no contradicting source.
- **[inference]** Keychain worsens it: access groups are team-prefixed, so even a preserved container would strand old-team keychain items — for an encrypted vault whose key lives in the keychain, cross-team reinstall is data loss even in the best case. **Operative rule: the FIRST install must happen under the Apple ID that will own every future refresh; never rotate burner IDs around the vault.**

## Q5. Net architecture ranking
- **(a) CI ships unsigned IPA → SideStore installs/refreshes on-device — the only fully viable architecture.** Bootstrap once (Q1), then per install: PR-comment link (Safari) → IPA → SideStore ("+" from Files) or **one-tap** via SideInstaller's `sideinstaller://install?url=<https .ipa>` + `open.html` handoff ([documented](https://github.com/FrizzleM/SideInstaller)) ≈ **3–4 taps**; **[inference]** best case: publish an AltStore/SideStore `source.json` (AltLoad's CI already generates one — [live-workflow-examples.md](live-workflow-examples.md)) so updates appear in-app = 1–2 taps. Renewal: profile dies day 7 → SideStore auto-refreshes in background **[documented]**, needing Wi-Fi + unlocked device (#496) + LocalDevVPN; scheduled refresh verified on iOS 26.6.1 ([discussion #1482](https://github.com/orgs/SideStore/discussions/1482), Sept 2026) — see [channels-and-limits.md](channels-and-limits.md) Q3. Risks: anisette instability/lockouts (official v3 or self-hosted + burner ID), pairing-file expiry after iOS updates.
- **(b) p12 → CI re-sign → OTA: dead** (Q3). Even ignoring export gaps, the CI-signed IPA embeds a profile the device must re-mint weekly anyway — no tap savings, more failure modes. The itms-services machinery in [ota-hosting-and-delivery.md](ota-hosting-and-delivery.md) becomes relevant only after a paid membership.
- **(c) Better:** nothing at $0. Exit ramps: $99/yr (TestFlight / year-long ad-hoc profiles / PAL), or Apparition once its no-computer iPhone install is verified.

## Q6. EU/DMA angle
- **[documented]** AltStore PAL installs only **notarized** apps from a **paid** developer account; no arbitrary-IPA import ([developer.altstore.io](https://developer.altstore.io/), [faq.altstore.io](https://faq.altstore.io/developers/distribute-with-altstore-pal) — full details in [channels-and-limits.md](channels-and-limits.md) Q4).
- **SideStore is NOT distributed via PAL:** **[inference from absence + mechanism]** SideStore's docs list only computer-based iLoader (fetched 2026-11-16); no PAL listing found; PAL apps must be notarized via App Store Connect, which free-provisioning-signed SideStore cannot be. **[unverified]** exhaustively (no official statement found).
- **[documented]** Nothing else in the EU framework helps a free team: marketplaces/Web Distribution still require paid membership + notarization after the 2026-10-01 CTF→CTC change ([Apple EU page](https://developer.apple.com/support/apps-in-the-eu/)). The free-provisioning route used here is worldwide and DMA-agnostic.

- No Apple primary source for the cross-team delete-then-reinstall rule (rests on maintainer/community reports).
- Burner Apple ID 2FA needs a reachable channel (SMS codes reported in #1658); sharing the owner's trusted number is **[inference]**, unverified.
