Device: Pixel 8, Android 17 (SDK 37), 7573 MB RAM, MemAvailable 1.2 to 2.3 GB during the runs, battery 24.8 to 26.6 C. App: QA build `com.therapylocal.app.qa`, APK sha256 `ae826a4d...ac4888`, litertlm-android 0.18.1. No app code changed. Raw json/logcat/meta files are not committed (public repo); they are in `.bigcache/pixel8/` on the host. Scripts: `scripts/pixel8/`.

Models, sha256 checked on host and on the device: `gemma-4-E2B-it.litertlm` 2588147712 bytes `18193810...97139a63c` (pinned commit 3d48132a); `embeddinggemma-2-740m.litertlm` 484622336 bytes `e7a8a220...f77f4c` (HF `main`, same hash as the catalogue).

## Setup problem found (not an app bug, but easy to hit)

A model file pushed into a directory that `adb shell mkdir -p` created (owner shell) is invisible to the app on this phone: Gemma gave "model file missing or incomplete", EmbeddingGemma gave `Failed to open LiteRT-LM file`. Fix: let the app create `files/models/` and `files/models/embeddinggemma-2-740m/` first (any probe run does it, owner = the app uid), then `adb push` only the file. After that both load. Did not test whether the shell-owned file alone (in an app-owned dir) is the issue; the directories were the variable I changed.

### Reply quality (the prompt asks for JSON lines with keys heading, content, evidence; Czech values)

Replies were byte-identical across the calls of one run and across both runs of one backend (CPU: 970 chars, GPU: 978 chars).

CPU reply, start (also the auto replies):
```
{"Klíč": "Petra", "Obsah": "Pocit vzdálenosti od sestry Lucie po přestěhování do Brna.", "Důkaz": "Moje sestra Lucie se přestěhovala do Brna a já mám pocit, že jsme si s ní teď strašně vzdálené."}
{"Klíč": "Stav stavu spánku", "Obsah": "Ztráta spánku a změna rytmu spánku.", "Důkaz": "Usínám až po půlnoci a v pět ráno se budím."}
```
GPU reply, start:
```
{"Klid": "Pohled na vztah s sestrou Lucie", "Obsah": "Klientka má pocit, že se s sestrou Lucie teď velmi vzdálená.", "Důkaz": "Usínám až po půlnoci a v pět ráno se budím."}
{"Klid": "Chybějící sociální interakce/Isolation", "Obsah": "Případné chybějící interakce s sestrou Lucie.", "Důkaz": "Usínám až po půlnoci a v pět ráno se budím."}
```
Both backends: five fenced JSON objects, wrapped in markdown fences, with keys that are not the requested ones (`Klíč/Obsah/Důkaz` on CPU, the first key `Klid` on GPU), cut at 400 tokens. Neither has a repeated key inside an object. The CPU quotes are real quotes from the input and match the claims. The GPU reply is worse: the sister claim and the "isolation" claim both cite the sleep sentence (wrong evidence), words like "finanční ztuhla" and "Prokrastinace" are invented, the first key is garbled. So GPU is fluent but wrong by the rule in the task, although the CPU also fails the key-name test on this prompt, so the CPU is only the better of two. I did not run the GPU in FLOAT32 (the QA APK has no switch for it that I found) or on a second prompt.
