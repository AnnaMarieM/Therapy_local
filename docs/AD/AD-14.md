# AD-14: Facts store who said them; the patient-only filter is applied when they are read

| | |
|---|---|
| Status | Proposed |
| Decided | `pending` |
| Decided by | `pending` |
| Drafted by | Claude (Sonnet), branch `feature/fact-extraction-pr3` (PR 3 of milestone M1) |

## Context
- Extraction (`Pipeline.extract`) reads plain window text; the windows carry no speaker labels ([`TranscriptWindows.stripSpeakerLabels`](../../app/src/main/java/com/therapylocal/app/facts/TranscriptWindows.kt)). The prompt asks for what the client said, but the model cannot see who spoke. The segments, however, keep the raw diarization id (`segments.speaker`), and roles are resolved from the append-only speaker map at read time ([AD-06](AD-06.md), [AD-10](AD-10.md)).
- A fact stored only `seg_idx`: no end of the quote, no time, no speaker. PR 4 (jump from a fact to its line) needs the exact segment range; the spec needs a speaker on each fact and patient-only by default.
- [AD-10](AD-10.md) point 5 says the speaker-map version is stored on facts but not compared by `refreshStale`, because roles are resolved at read time and a swap must not re-run the LLM.

## Decision
1. **A fact stores where its quote is, not what the speaker is.** `facts` (and `mentions`) get `seg_to` (last segment of the quote; `seg_idx` stays the first), `start_ms` and `end_ms` (start of the first segment, end of the last) and `speaker` (the raw diarization id of the first segment; null when the recording was not diarized). All are derived at commit from the fact's quote and the current transcript (`FactParser.segmentSpan`, `FactSpans.of`). Schema change in the create path only ([AD-11](AD-11.md)), `VERSION` 7.
2. **The role is resolved at read time** from the raw id and the session's current speaker map (`FactSpeakers.roleOf`). It is never stored, so a roles swap (a new speaker-map version) changes what is shown with no extraction and no write to facts. Facts do not become stale for a map change (unchanged from AD-10 point 5).
3. **Reads default to the patient's facts.** `MindStore.facts`, `nearestFacts`, `factEmbeddings` and `factOccurrences` take `includeTherapist: Boolean = false`. By default a fact is hidden when its role is therapist or other; it is shown when its role is patient or cannot be resolved (no map, no raw id, an id the map does not know). The filter runs before the nearest-k cut and the mention count counts only mentions visible under the same rule. Only the commit step (duplicate check and category centroids must see every stored fact), the client-deletion check and the debug export pass `true`.
4. **A fact is attributed to the speaker of the first segment of its quote.** A quote that crosses a turn change belongs to whoever started it.
5. **Several facts per sentence** are allowed and expected: each has its own quote and so its own span. Repeats are merged by content, or by the same quote and nearly the same words (`FactParser.dedupe`); facts that only share a sentence are kept.

## Alternatives considered
- **Store the role on the fact at commit.** Simple reads, but a swap would need every fact of the session rewritten or re-extracted, or would show the wrong people until then. Rejected.
- **Filter at extraction (drop therapist facts).** Smaller table, but a swap or a wrong guess needs a full re-extraction, and the therapist's lines would be lost. Rejected.
- **Make a roles swap stale the facts.** Rejected in AD-10: it re-runs the LLM for nothing.
- **Label the speakers in the extraction input.** Would let the model separate the two speakers itself. It changes the window text, the cache keys and the prompt together and cannot be checked without a device run, so it is left to a later change.

## Consequences
- **Better:** one source of truth for who is a patient (the speaker map); a swap is instant and free; PR 4 can open the exact lines and times of a fact; the extraction cache keeps its key.
- **Worse, accepted:** every fact read also reads the session maps and the client's mentions (a few small queries, no join in the hot path); because the prompt asks for the client's facts and the input has no labels, therapist facts are stored only when the model quotes a therapist line, so a swap shows more or fewer facts depending on what the model extracted; the existing database of every test device is wiped (AD-11).
- **Still true:** facts are never edited; a stale generation is superseded.

## Verification
- **JVM tests:** span and time range from quotes (inside a segment, across segments, every planted sentence of `e2e/sittings/scripts`); several facts per sentence and the dedupe; role resolution, the default filter and a swap (`FactSpeakersTest`, `FactSpansTest`).
- **Device tests (`DataLayerTest`, compile only locally):** round trip of span and speaker; default read is patient-only for facts, mentions, nearest and embeddings; a swap changes the read without a write and does not make facts stale; a promoted mention keeps its span and speaker.
- **Not verified:** the extraction prompt on a model, SQLCipher on a device.
