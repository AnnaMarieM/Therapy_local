# AD-14: Facts are extracted from the role-labelled dialogue, store who said them, and are shown patient-only by default

## Context
- A patient's answer ("yes, since March") means nothing without the therapist's question. Extraction ran on plain window text without speakers ([`Pipeline.extractUser`](../../app/src/main/java/com/therapylocal/app/jobs/Pipeline.kt), `TranscriptWindows.bySegments`): the model could not see who spoke or what was asked, and could take the therapist's own words for facts.
- The app already has the role-labelled transcript: `TranscriptFormat` (a `[hh:mm:ss]` line, then `Therapist:` / `Patient:` and the text), used by the screen (`ClientRepository.formattedTranscript`) and the summary ([AD-12](AD-12.md)). Roles come from the append-only speaker map ([AD-06](AD-06.md), [AD-10](AD-10.md)).
- A fact stored only `seg_idx`: no end of the quote, no time, no speaker. PR 4 (jump from a fact to its line) needs the exact segment range.
- [AD-10](AD-10.md) point 5 says the speaker-map version is stored on facts but not compared by `refreshStale`, "because roles are resolved at read time and extraction reads text only", so a swap must not re-run the LLM. With labelled input the second half is false.

## Decision
1. **Extraction reads the labelled dialogue.** The windows are the transcript formatted by `TranscriptFormat` with the labels of the session's current speaker map (`ExtractionDialogue`, `TranscriptWindows.byTurns`): cut on turn boundaries, each later window starting with the turns before its first new one (up to the overlap) so an answer comes with its question, a turn longer than a window cut by words with its header repeated. `stripSpeakerLabels` is not used on this path. The prompts (EN, CS) say the input is a dialogue and ask for what the patient states or confirms, written so that it can be read alone, and not for the therapist's own statements.
2. **This amends AD-10 point 5.** The speaker-map version is now compared for facts and windows: `MindStore.refreshStale` marks a session's windows and facts stale when their `prov_speaker_map_version` is not the current map's (as `refreshSummaryStale` already does for summaries). The extraction cache key is prompt version, model, speaker-map version of the window and window text, so a swap invalidates it. **A roles swap therefore re-runs extraction for that session** (through the existing rebuild, `Reprocess`). The cost is accepted: a swap changes what the facts mean, because the model read the labels. A fact's provenance records the map version the extraction used (from its cache key), not the one current at commit.
3. **A fact stores where its quote is, not what the speaker is.** `facts` and `mentions` get `seg_to` (last segment of the quote; `seg_idx` stays the first), `start_ms`, `end_ms` and `speaker` (the raw diarization id of the first segment; null when not diarized). All are derived at commit from the quote and the current transcript (`FactParser.segmentSpan`, `FactSpans.of`). A quote is grounded and located in the segment texts, never in a label or a time. Schema in the create path only ([AD-11](AD-11.md)), `VERSION` 7.
4. **Reads default to the patient's facts, filtered at read time as a safety net.** `MindStore.facts`, `nearestFacts`, `factEmbeddings` and `factOccurrences` take `includeTherapist: Boolean = false`; the role is resolved from the raw id and the current map on every read (`FactSpeakers`), never stored. Therapist and other are hidden; patient and unresolved (no map, no raw id, unknown id) are shown. The filter runs before the nearest-k cut and `mentionCount` counts visible mentions only. Only the commit step, the client-deletion check and the debug export pass `true`. Between a swap and its rebuild the filter already follows the new map, and a fact is attributed to the speaker of the first segment of its quote.
5. **Several facts per sentence** are allowed: each has its own quote and so its own span. Repeats are merged by content, or by the same quote and nearly the same words (`FactParser.dedupe`).

## Alternatives considered
- **Keep plain-text extraction and only filter at read time** (the first draft of this decision). Facts need no re-extraction on a swap, but the model never sees the question and cannot tell the speakers. Rejected: the facts would be wrong, not only mis-attributed.
- **Store the role on the fact.** Rejected: a swap would leave wrong roles until the rebuild; resolving at read time costs a few small queries.
- **Filter at extraction (drop therapist turns from the input).** The answer would lose its question. Rejected.
- **Do not make a swap stale the facts; accept labels from the old map until a manual rebuild.** Rejected: facts would silently mean the wrong thing.

## Consequences
- **Better:** the model sees the question with the answer and who said each line; a patient's short answer becomes a self-contained fact; PR 4 can open the exact lines and times of a fact; a swap is never silently wrong.
- **Worse, accepted:** a roles swap re-runs the session's windows (embeddings), extraction and commit (and the later sessions' commits); windows, and so search snippets, now contain the labels and time lines; the labelled input is a little longer for the same window budget; every fact read also reads the session maps and the client's mentions; the existing database of every test device is wiped (AD-11).
- **Not checked on a model:** the prompt changes and the quality of extraction from dialogue have not been run; see Verification.
- **Still true:** facts are never edited; a stale generation is superseded (AD-10 point 6).

## Verification
- **JVM tests:** windows keep turn boundaries and carry the labels, context before a later window, long turns, a swap changes the labels, the cache key holds the map version, a quote still resolves to its segment range, time range and speaker (`ExtractionDialogueTest`, `FactSpansTest`, `FactSpeakersTest`, including every planted sentence of `e2e/sittings/scripts`).
- **Device tests (`DataLayerTest`):** span and speaker round trip; default patient-only reads; a swap makes windows and facts stale and a rebuild clears it; a promoted mention keeps its span and speaker.
- **To check on a device (not done):** an e2e sittings run on the QA build, `e2e/.venv/bin/python e2e/sittings/run_device.py --out e2e/sittings/results/run1`, then `python3 e2e/sittings/report.py --results e2e/sittings/results/run1/results.json`, compared with a run of `main`.
