# AD-02: One model per role, Canary is the only speech recogniser

## Context

The app ships four ways to turn speech into text, chosen by the `engine` setting (`canary`, `whisper`, `gemma`):

- **Canary 1B v2** (int8, sherpa-onnx, `SherpaCanaryAsr`): the default (`ModelRegistry.DEFAULT_ENGINE`), 25 European languages including Czech and English, about 1.4 GB.
- **Whisper** (int8, sherpa-onnx, `SherpaWhisperAsr`): nine model specs (tiny to large-v3, plus English-only builds), a `whisper_size` setting, and one download per client language (`SpeechLanguages.inUse`, `ModelRegistry.whisperFor`).
- **Parakeet TDT 0.6B v3** (`ModelRegistry.PARAKEET_V3`, `SherpaParakeetAsr`): defined, but no setting selects it.
- **Gemma speech recognition** (`GemmaAsr`): the memory LLM with its audio encoder (`MemoryLlm.load(withAudio = true)`). It falls back to Canary when it fails to load (`ModelPool.onAsrLlmFailed`), but not when it fails mid-transcription.

Each path is its own download, its own native load through the backend ladder, its own failure modes and its own tests. Gemma speech recognition is the worst of them for memory: the audio encoder sits on top of the LLM in unified RAM, it shares the LLM engine, and it toggles the process-global LiteRT `ExperimentalFlags`. Under [AD-01](AD-01.md), every path would also need its own calls across the process boundary.

The app supports two speech languages, English and Czech (`SpeechLanguage`). Canary covers both.

## Decision

1. **Speech recognition is Canary 1B v2 only.** It was chosen for its Czech, which is what the sessions are mostly in. There is no speech-engine setting. The client's language is still passed to Canary per recording.
2. **Gemma 4 is text only.** It processes the transcribed chunks in the pipeline (windows, extraction, review, commit) and never receives audio.
3. **EmbeddingGemma 2 keeps embedding audio.** Live cues and audio search embed audio directly into the shared 768-d space. That is embedding, not recognition, and it does not change.
4. **The Gemma E2B / E4B choice stays.** The two are sizes of the same release, picked by RAM (`ModelChoice`), not an older and a newer model.
5. **Removed from the code:**
   - `GemmaAsr`;
   - the audio path in `MemoryLlm` (`withAudio` and the audio options);
   - `ModelPool.audioLlm` and `onAsrLlmFailed`, and the `asrOnLlm` wiring in `DeviceModels`;
   - every Whisper spec, `SherpaWhisperAsr`, the `whisper_size` setting and `ModelRegistry.whisperFor`;
   - `PARAKEET_V3` and `SherpaParakeetAsr`;
   - the engine and Whisper-size chips in the developer screen, and their strings (`values`, `values-cs`).
6. **Existing installs migrate once, at start-up, and log it.**
   - The `engine` and `whisper_size` settings are deleted. The log line is `speech_engine_migrated from=<old engine> whisper_size=<old size>`, written only if either setting was present.
   - Downloaded Whisper and Parakeet files are deleted to free storage. The log line is `model_files_removed id=<model> bytes=<n>`.
   - Transcripts already made are untouched, and pending `transcribe` jobs run with Canary.
   - The migration never throws: a file it cannot delete is logged and left in place.
7. **One model per role from now on.** Moving to a newer model replaces the old one through a new decision. It is not added next to it as a setting.

## Alternatives considered

- **Parakeet TDT 0.6B v3 only.** Smaller (about 670 MB) and faster, with the same 25 languages. Rejected: Canary is better at Czech.
- **Keep Whisper as a small fallback for weak phones.** Rejected: it keeps nine specs, a size setting and per-language downloads, which is the complexity this decision removes. The backend ladder already falls back to the CPU for Canary.
- **Keep Gemma speech recognition.** Rejected for the memory reasons in Context. An LLM failure would also take transcription with it, and AD-01's `:batch` contract would have to carry audio into the LLM.

## Consequences

- **Better:**
  - one recogniser to download, load, test and log;
  - the AD-01 host contract has a single `transcribe` path, and the LLM in `:batch` is text only, so the constrained-decoding flag in `ask` is the only `ExperimentalFlags` user there;
  - less memory pressure in `:batch`, since no audio encoder sits on the LLM;
  - fewer settings and fewer things a field log has to explain.
- **Worse, accepted:**
  - every install needs the 1.4 GB Canary download, with no smaller option for a phone short on storage;
  - adding a language now means checking that Canary supports it.
- **Still true:**
  - Canary runs on the CPU through the backend ladder (NNAPI only in the evaluations);
  - audio embedding is unchanged.

## Verification

- **Unit tests:**
  - the migration with every old `engine` / `whisper_size` value, an empty store, and files that cannot be deleted. It never throws, and the log lines are as above;
  - `ModelSetup` asks for Canary for every language set;
  - nothing references Gemma audio.
- **On-device tests:**
  - a recording transcribes with Canary in `:batch`;
  - a stored `engine=gemma` or `engine=whisper` from an older version ends up on Canary with one migration line.
- `grep -rn -i "whisper\|parakeet\|GemmaAsr\|withAudio\|audioLlm" app/src/main` returns nothing except the migration.
