# AD-16: The QA build has a control API for adb; no other build has it

| | |

## What
- The QA build (`com.therapylocal.app.qa`) gets one control API for adb: an exported content provider, called with `adb shell content call`, that answers only the adb shell user. No network, no socket.
- Commands, each running the same code as the UI: `status`, `setup`, `unlock`; **import** (`seed_clients`, `import_clients`, `import_session` with audio or a transcript; whole sets of patients and sessions at once); **export** (clients, sessions, transcripts with speaker ids and roles, speaker-map versions, facts with spans, summaries, as JSON files); `wait`, `swap_roles`, `set_summary_format`, `reset`.
- **Every backend function is callable**: transcribe, diarize, embed, ask (LLM), the pipeline jobs, with the backend chosen per call (CPU, GPU, NPU), and every call returns its result and timings. The harness and the e2e sittings then run on this same QA build on the phone, where the GPU and NPU are much faster than on a CI emulator.
- While the vault is locked only `status`, `setup` and `unlock` work. `reset` never deletes models, and data-deleting commands refuse unless the app id ends in `.qa`.
- It is compiled from the `qa` source set. `release`, `debug` and `feel` do not have it, and the `build` job fails if the release APK or its merged manifest contains any trace of it.
- Clinical text is never logged. Results are JSON files, not logcat. A host script `qa/qa-api.sh` and `docs/QA_API.md` wrap it.

## Why
- Driving QA today takes UI taps and one-off scripts that break with every UI change. One scriptable surface serves tests, the e2e runner, the harness and manual checks.
- The phone's GPU and NPU are what we need to measure, and CI emulators have neither. The same build must run the harness there, without a second harness build.
- Rejected: a loopback HTTP server (any app on the phone can reach `localhost`), a debug menu (not scriptable), and putting it in `debug` (same app id as the real app, which may sit on the same phone with a real vault).
- Accepted cost: anyone with adb on a QA phone can read and change its data. QA already allows that and never holds real data.
