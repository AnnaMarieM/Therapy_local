# AD-17: All processing runs in English; only what is shown is translated

| | |
|---|---|
| Status | Proposed (draft, not decided; PR is not to be merged until the side-by-side test is done) |
| Decided | — |
| Decided by | — |
| Drafted by | Claude (Opus), branch `feature/english-pivot` |

## What
- Canary still transcribes in the client's language. The transcript is kept as spoken; that is what the transcript screen shows.
- A new step translates the transcript into English, segment by segment. Every model job after that reads only the English text: roles, windows, extraction, duplicate review, categories and the summary. The prompts are always the English ones.
- Facts and summaries are stored in English. A last step translates what the screens show (fact headings and contents, summary text, live cues) into the app's language and caches it. Categories are mapped through the fixed taxonomy, with no model call.
- Changing the app language only re-translates what is shown. Nothing is extracted again.
- For now the translator is the same Gemma that does the rest (AD-02 stays: no new model). A dedicated translation model can replace it later behind the same step.
- A setting `processing_language` (`english` | `native`) keeps today's behaviour reachable, so one QA build can run the same sessions both ways and compare them.

## Why
- The local models are at their smartest in English. Our working assumption: E4B reasoning in Czech is weaker than E2B reasoning in English. Extraction, the duplicate check and summaries are the hard part; translation is easy by comparison.
- What matters is understanding the session correctly. If a translated label is a bit clumsy or a word is mangled but the point is right, the model understood the Czech, and that is the goal. Wording can be polished later, by hand or with a better translator.
- One language inside means one set of prompts to tune, one taxonomy, and caches and benchmarks that compare across clients.
- Rejected for now: Canary speech translation (it needs the audio, which is deleted after a week, and text-imported test transcripts have none) and keeping Czech prompts (measured worse, and twice the prompt work).
- Accepted cost: the extra translation passes (in and out) take phone time and battery, translation errors propagate into the facts, and a quote shown as evidence is the English one unless it is mapped back to the original segment.
- Verify before deciding: run Czech sessions in both modes on the same build and phone, then compare facts, duplicate verdicts, roles and summaries, plus the processing time.
