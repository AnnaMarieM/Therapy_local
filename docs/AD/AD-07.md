# AD-07: The diarizer always looks for exactly two speakers

| | |
|---|---|
| Status | Accepted |
| Decided | `2026-11-09 00:12 CET` |
| Decided by | Martin Hajný (@hajnina) |
| Drafted by | Claude (Opus), PR 1 transcript pipeline |

## Context
- [AD-06](AD-06.md) (accepted in the same PR) adds speaker diarization: sherpa-onnx `OfflineSpeakerDiarization` runs over the whole recording in `:batch`, then each speaker turn is transcribed.
- Its clustering takes either a fixed speaker count (`numClusters`) or, with `numClusters = -1`, a distance threshold (`DiarizeRunner.CLUSTER_THRESHOLD = 0.5`, the value sherpa-onnx's examples use) that decides the count from the audio.
- The pipeline passes the count as `MemoryConfig.DIARIZE_SPEAKERS_HINT`; a value above 0 becomes `numClusters`, 0 means the threshold decides.
- The app records one-to-one therapy: one therapist and one patient. It does not record couples or family sessions.
- A threshold can split one voice into two clusters (a voice that changes with emotion or distance from the phone, room noise) or merge two similar voices. A fixed count cannot do the first.
- A recording can still hold only one voice (a dictated note, a patient who did not come through).

## Decision
1. **`DIARIZE_SPEAKERS_HINT = 2`: every recording is diarized into exactly two speakers**, `S0` and `S1`. The role guess names one therapist and one patient.
2. **No exception for a one-voice recording.** It gets two speakers as well, and a role guess. There is no check on how the speech is shared between the two.
3. The AD-06 fallback for fewer than two speakers stays in the code as a safety net (planning can still absorb one speaker's turns), but it is no longer the way a one-voice recording is handled.

## Alternatives considered
- **Let the threshold decide (`DIARIZE_SPEAKERS_HINT = 0`).** This was the first draft of this record. It handles group sessions and reports one-voice recordings as one speaker. Rejected: the app has no group sessions, and the threshold can show a spurious third speaker in a one-to-one session, which the swap cannot fix.
- **Force two, then treat a speaker with under ~10% of the speech time as noise (one-voice check).** It would keep a dictated note from getting an invented second speaker. Rejected for now: one more threshold to tune, and one-voice recordings are rare.

## Consequences
- **Better:**
  - one-to-one sessions always come out as two speakers, never three;
  - the therapist/patient swap in PR 1 always applies, since there are always exactly two roles to swap.
- **Worse, accepted:**
  - a one-voice recording gets an invented second speaker: some of the voice's turns are labelled as another person, and the role guess is meaningless there;
  - a session with a third voice (an interpreter, a parent at the start) has that voice merged into the therapist or the patient.
- **Still true:** the count is one constant; changing it needs a new decision that supersedes this one.

## Verification
- **Unit tests:** `MemoryConfig.DIARIZE_SPEAKERS_HINT` is 2; a hint above 0 reaches sherpa-onnx as `numClusters`; hint 0 would be `numClusters = -1` with the threshold.
- **On-device:** two-person recordings (Czech and English) give `diarize_done speakers=2`; the share of words attributed to the right speaker is measured by the e2e sittings (`e2e/sittings`). The single-voice sitting shows how badly an invented second speaker reads.
