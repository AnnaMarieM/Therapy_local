# AD-04: Engine hosts exit quietly on a crash

| | |
|---|---|
| Status | Accepted |
| Decided | `2026-11-06 22:20 CET` |
| Decided by | Martin Hajný (@hajnina) |

## Context
- AD-01 put model inference in `:live` and `:batch` so a model crash never closes the app. Issue #51 shows this does not hold on a real phone (Xiaomi, HyperOS, Android 16): after a native crash of `:batch` (exit record `APP CRASH(NATIVE)`) Android showed `Application Error: com.therapylocal.app` over the whole app, although only the background host had died.
- The dialog and the tombstone come from the system's crash reporting, which a process enters in two ways: an uncaught Java exception reaches the platform handler (`RuntimeInit`, which reports to the system), and a fatal native signal reaches debuggerd, which writes a tombstone and tells the system about a native crash. Both treat the crash as a crash of the app, not of one process.
- The host already ends itself with `Runtime.halt(10/11/12)` on purpose; the system records that as `EXIT_SELF` with the status and shows nothing (AD-01).
- `ApplicationExitInfo` keeps the exit status for a self-exit, so a crash that ends as `EXIT_SELF` still tells main what happened.
- ART uses SIGSEGV for implicit null checks and stack-overflow detection. A handler that replaces ART's breaks every managed null check. `libsigchain` (ART) interposes `sigaction`: `app_process` lists it in `DT_NEEDED` "so all code in app_process and the libraries it loads find libsigchain symbols before libc symbols" (`frameworks/base/cmds/app_process/Android.bp`). `SignalChain::Handler` (`art/sigchainlib/sigchain.cc`) runs ART's special handlers first and passes a signal to the user handler only if they return false.

## Decision
1. A host process (never main) installs a native handler, `libquietcrash.so` (`app/src/main/cpp/quietcrash.c`, loaded by `NativeQuietCrash` from the host branch of `App.onCreate`), for SIGSEGV, SIGBUS, SIGABRT, SIGFPE, SIGILL, SIGSYS and SIGTRAP (on arm64 `brk`, so `__builtin_trap` and UBSan traps arrive as SIGTRAP). The handler only calls `_exit(100 + signal)`. It is registered with plain `sigaction`, so it goes through libsigchain behind ART's handler. `install` first checks with `dladdr` that `sigaction` resolves to `libsigchain`; if not it installs nothing (a libc `sigaction` would replace ART's handler) and `quiet_crash_install` logs `refused_not_chained`. SA_ONSTACK uses the alternate stack ART gives every thread it creates.
2. The host's uncaught-exception handler (`AppLog.installCrashHandler(redacted = true, haltCode = 13)`) logs the redacted line, flushes it, and calls `Runtime.getRuntime().halt(13)`. It no longer calls the platform handler, which also makes the sanitized-copy delegation of review finding F1 unnecessary (the redacted log line stays).
3. `HostExit` gets `JAVA_CRASH(13)` and the native range `NATIVE_BASE + signal` (101..164). `ExitReasons.map` reads `EXIT_SELF` with a native status as `NATIVE_CRASH` (description `signal N`) and status 13 as `CRASH`; 10, 11 and 12 stay benign. Everything downstream (BackendGuard strikes, recovery at start-up, Settings, `engine_died`) reads the kind, so a quiet native crash is struck exactly like a `CRASH_NATIVE`.
4. The library is compiled from one C file with the pinned NDK clang by a Gradle task, in the build container. `arm64-v8a` is in every APK; `x86_64` only in debug (the CI emulator). Debug symbols are not stripped by AGP (`keepDebugSymbols`), so adding the NDK changes no existing library.

## Alternatives considered
- **Run the hosts as `isolatedProcess`.** Rejected: an isolated process has no access to the app's files (the host writes its own log to the app's external files dir) and runs under a separate uid, which is a large change to AD-01; it is not shown that the system would stay silent about a crash of it either.
- **`hide_error_dialogs` / suppress the dialog by setting.** Rejected: it is a global setting that needs `WRITE_SECURE_SETTINGS`, not available to an app, and hides every app's crash, not only ours.
- **Leave the dialog.** Rejected: it covers the whole app during a session and blocks input until dismissed, for a failure the app recovers from by itself.
- **Handle only the Java crash, accept the tombstone.** Rejected: the reported crash was native, and the tombstone is the part that can hold patient text.
- **CMake and Ninja through `externalNativeBuild`.** Rejected: CMake and Ninja are x86_64-only prebuilts that start themselves as child processes (`try_compile`, `cmake -E`); under qemu-user on an arm64 builder a child cannot be started without binfmt on the host, which a container cannot rely on. clang is a single process and needs only launchers. One file does not need a build generator.
- **Use `libunwind`/Breakpad/Crashpad.** Rejected: we want no dump, only a status.

## Consequences
- Better: a host crash is invisible to the user; no tombstone or DropBox entry for the signals we catch (docs/SECURITY.md); main still learns kind and signal from the exit record (`engine_died ... exit_kind=native_crash description="signal 11"`).
- Worse: C is a new runtime in a Kotlin app; the build image holds the NDK (about 2 GB after pruning) and on arm64 its clang runs under qemu-user; the handler hides the stack from every tool (no tombstone for us to read when debugging; logcat and the `engine_died` line carry the signal and the model phase).
- Accepted, still true: a crash before the handler is installed, a refused install, SIGKILL, and a stack overflow on a native thread with no alternate stack still behave as before (a tombstone and possibly the dialog). A fault in code of the handler cannot happen: it only calls `_exit`.
- A device that interposes `sigaction` differently makes the install refuse and the old behaviour returns, visibly in the log.

## Verification
- JVM: `QuietCrashExitTest` (mapping of 101..164, 13, 10..12; connection classification; strikes), `CrashHandlerTest` (halt after the log, platform handler untouched in main).
- Device (`ProbeTest` P-01: SEGV and ABRT end as `EXIT_SELF` with status 111 and 106, mapped to native crash; P-05: three crashes with `MainActivity` in front, the window dump is polled during and 3 s after each crash and never shows `Application Error` or `keeps stopping` for our package).
- Manual, on the phone of issue #51: crash `:batch` with the fault plan (`do.kind=signal`), expect no dialog, `quiet_crash_install result=installed sigaction_owner=.../libsigchain.so`, and `engine_died exit_kind=native_crash`.
- `scripts/build.sh full` is green, the APK holds `lib/arm64-v8a/libquietcrash.so` (and `lib/x86_64` in debug only) and the arm64 and x86_64 builders produce the same sha256.
