## Context
- The shipped app is Android only: Kotlin, Jetpack Compose, 23,666 lines in `app/src/main/java`. Model inference runs in separate engine-host processes over the NDK ([AD-01](AD-01.md)): LiteRT `litertlm` for Gemma, sherpa-onnx for Canary and the diarizer ([AD-02](AD-02.md), [AD-06](AD-06.md)), whisper.cpp in `:batch` for the Quality workflow (AD-22, quality tiers; recorded on its own branch, not merged into `ios` yet).
- The iOS baseline landed under `ios/` at commit `1f70fa9`: a SwiftUI replica (MindVault, 5,059 lines of Swift in `Sources`+`Tests` when this was drafted; the engine packages under `ios/Packages/` are counted separately as they land) with the encrypted vault, the screens and a Linux-tested SwiftPM core. The app target has never been compiled by Xcode (syntax-parsed on Linux only), and speech recognition, embeddings and fact extraction are placeholders behind the contracts in [`ios/CONTRACTS.md`](../../ios/CONTRACTS.md).
- **No Apple Developer account exists**: no certificates, no provisioning profiles, no App Store Connect key. CI runs on GitHub runners only, and the repository holds zero Apple secrets.
- The models are large HF downloads with pinned sha256 (`app/src/main/java/com/therapylocal/app/models/ModelSpec.kt`): Gemma E2B 2.59 GB, E4B 3.66 GB, EmbeddingGemma 740M 485 MB, Canary int8 1.41 GB, diarization 32 MB, whisper large-v3 q8_0 1.66 GB (no host URL yet). The iOS equivalents run whisper.cpp and llama.cpp on Metal and ONNX on the CPU, with their own HF files: whisper large-v3 f16 3.10 GB, q5_0 1.08 GB, turbo q8_0 0.87 GB (`ggerganov/whisper.cpp`), and Gemma GGUF from `ggml-org/gemma-4-E2B-it-GGUF` (Q4_0 2.84 GB, Q8_0 4.97 GB; E4B Q4_0 4.59 GB). One model per role is a download of roughly 0.9-5 GB, several GB on the device.
- The rolling Android release pattern exists: `ci.yml` job `release-main` publishes `Therapy-main.apk` with its `.sha256` as the prerelease `main`, replaced on every push, after the tests have passed.
- `ios/KANBAN.md` (lane R1): no release before a person has run a session end to end on an iPhone — whisper, Gemma and embeddings actually on the device.

## Decision
1. **The iOS app is a native SwiftUI codebase under `ios/`.** A second codebase, not a shared cross-platform layer. What the two share is the contract, not code: [`ios/CONTRACTS.md`](../../ios/CONTRACTS.md) freezes the domain models, the 20/5 chunk math, the extractive facts with the fixed taxonomy, the encrypted vault shape (AES-256-GCM, key held only while unlocked) and the no-network rule. Behavior changes go through the contract, not through copying Kotlin.
2. **Engine equivalence, one model per role carried over.** ASR is whisper.cpp on Metal; the memory LLM is Gemma via llama.cpp on Metal (GGUF); diarization runs the same ONNX files Android uses (pyannote segmentation-3.0 + WeSpeaker, via sherpa-onnx). Text embeddings on iOS start on Apple's `NLEmbedding` (512-d, English) plus the hashing fallback — a **different vector space** from Android's EmbeddingGemma 768-d, never mixed in one index (CONTRACTS.md `EmbeddingProviding` allows `isSemantic: false`); running EmbeddingGemma's ONNX on iOS is a wiring-lane follow-up, not v1. Model files are downloaded at runtime with a pinned sha256 like `app/build.gradle.kts` does for sherpa-onnx, and are never committed.
3. **Release channel: a rolling unsigned-IPA prerelease `ios-main`**, mirroring `release-main`: `MnemoThera-ios-unsigned.ipa` with its `.sha256` plus the simulator zip, replaced on every publish, built by CI on macOS runners as an unsigned archive (no signing identity needed).
4. **Nothing publishes before R1.** The workflow is drafted now (`.github/workflows/ios-release.yml`) and disabled; it is enabled only when R1's parity checklist has passed and Martin accepts the release. Enabling it is the R1 card's deliverable, not a default.
5. **Distribution until an Apple Developer account exists: sideload only, AltStore Classic 2.2+ first.** AltStore (iOS 17.4+ on the phone, AltServer 1.7.4 Windows / 1.7.3 macOS) is the primary path because it is the only sideloader that preserves the `increased-memory-limit` entitlement the multi-GB models need on re-sign (Sideloadly and SideStore do not). Sideloadly is the fallback. With a free Apple ID the build is valid 7 days, then it must be re-signed; at most 3 sideloaded apps per Apple ID and 10 new App IDs per 7 days. When an account arrives, TestFlight (fastlane or `altool` with an App Store Connect API key) takes over for anything beyond the QA channel; the unsigned rolling IPA may stay as the QA channel or be retired then.
6. **No Apple secrets are stored in the repository.** None exist today; the release job uses only `GITHUB_TOKEN`.

## Alternatives considered
- **Kotlin Multiplatform / Compose Multiplatform (share the Kotlin).** Rejected. The shareable part is a fraction of the 24k lines: the engine layer is Android-coupled (engine-host processes over the NDK, AD-01; LiteRT `litertlm`, sherpa-onnx JNI, whisper.cpp JNI), the UI is Compose, and iOS would still need the native Metal, AVAudio and Xcode work on top. The cost is close to a rewrite of the app with a KMP layer bolted on, and the iOS side would end up native anyway — two clean codebases with a frozen contract cost less and hide nothing.
- **Electron/web-style shared UI (web app or web view).** Rejected. Audio fidelity (16 kHz chunked capture, interruptions, background recording), vault fidelity (Keychain, file protection, AES-256-GCM at rest) and on-device model performance are exactly what a web layer compromises, and the app is on-device-only by contract. A web view would also not run whisper.cpp or llama.cpp on Metal.

## Consequences
- **Better:** native Metal inference for whisper.cpp and llama.cpp and AVAudioEngine capture, the right tools for the job; each platform keeps its best local stack; the release pipeline exists and is one flag away when R1 passes; nothing secret is stored, so nothing can leak.
- **Worse, accepted:** two codebases kept in contract by hand — every change to shared behavior is a CONTRACTS.md review; the model download, job queue and vault logic exist twice; the iOS app lags Android where the port has no equivalent yet (the EmbeddingGemma audio encoder has no iOS counterpart, so live cues may run on text embeddings only at first; the full Android feature set is not v1 scope per `ios/KANBAN.md`).
- **Still true / accepted limits:** no TestFlight and no App Store until an Apple Developer account exists; sideloaded builds stop working after 7 days and must be re-signed by the person who installed them; the unsigned IPA must be signed before it can run at all; the macOS runner lane is the port's slow CI check (minutes are free for public repositories, AD-13's wall-clock rule applies to it as to every lane).

## Verification
- The draft `ios-release.yml` publishes nothing while dormant, by construction: the only trigger is `workflow_dispatch` with a `publish` input that **defaults to false** — a dispatch without the flag is a dry run (resolve the build, download the artifacts, verify names and hashes, publish nothing), and the release job additionally requires the `ios` ref. Two more operational facts, recorded because the review proved both: a `workflow_dispatch` workflow only fires when the file exists on the **default branch**, so landing `ios-release.yml` on `main` is step one of the R1 runbook; and the artifacts it downloads carry the exact names `ios.yml` uploads (kept in lockstep — a name drift is the failure the review flagged first).
- The packages test on Linux in `swift:6.3` and compile for iOS in CI (B1/C1/D1 and A2 lane definitions of done: XcodeGen generates the project, the simulator and unsigned device builds succeed, unit tests pass on a macOS runner).
- The published `.ipa.sha256` lets the person verify the download before signing it (the release job generates the hash in-job, so it covers exactly the published bytes).
- **R1, person-verified:** record, transcribe, extract and summarize a real session end to end on an iPhone with the on-device models; then the workflow is enabled, `ios-main` is published, and Martin accepts the release.
