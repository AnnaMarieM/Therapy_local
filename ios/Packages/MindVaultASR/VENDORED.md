## Touched files: none

Every file under `Vendored/whisper/` is byte-identical to upstream at that
commit, including the three files that SwiftPM needs in their own directory
(`ggml/src/registry/`: `ggml-backend-reg.cpp`, `ggml-backend-dl.cpp`,
`ggml-backend-dl.h` — moved, not edited, because a SwiftPM target owns exactly
one directory).

Upstream's CMake is not vendored; `Package.swift` restates the target set by
hand (`CGgmlBase`, `CGgmlCpu`, `CGgmlMetal`, `CGgmlRegistry`, `CWhisperCore`,
`CWhisper`), mirroring `ggml/CMakeLists.txt` and `ggml/src/ggml-metal/CMakeLists.txt`.
To bump the pin: replace the tree, then re-check the target `sources:` lists
against the upstream CMake, and copy the Metal kernels again (see below).

## The Metal kernels exist twice on purpose

`Sources/MindVaultASR/kernels/` + `Sources/MindVaultASR/ggml-metal-impl.h` +
`Sources/MindVaultASR/ggml-common.h` are copies of
`Vendored/whisper/ggml/src/ggml-metal/kernels/`,
`Vendored/whisper/ggml/src/ggml-metal/ggml-metal-impl.h` and
`Vendored/whisper/ggml/src/ggml-common.h`.

Reason: SwiftPM cannot compile Metal sources the way upstream CMake does. The
two upstream routes are `xcrun metal` → `default.metallib` (a build-time tool
SwiftPM has no way to run for a dependency) and `GGML_METAL_EMBED_LIBRARY`
(ASM `incbin` of every kernel, generated by CMake). Neither is reachable from a
`Package.swift`, and a resource of a Clang target is not reachable either: that
lands in `<Package>_CGgmlMetal.bundle`, which the loader only looks in for
`default.metallib`/`kernels/<name>` by name (no path separators) — and
SwiftPM generates no `resource_bundle_accessor.h` for Clang targets, so
`Package.swift` has to spell `SWIFTPM_MODULE_BUNDLE` itself (it does, as the
vendored file's "NSBundle Path Hack": the bundle the class was loaded from).

So the sources ship as resources of the Swift target and
`WhisperEngine.init` sets `GGML_METAL_PATH_RESOURCES` to the bundle directory
before the first whisper init. ggml then compiles `<dir>/kernels/<kind>.metal`
on the device — its own from-source fallback, the one `whisper-cli` uses when no
metallib is installed. The bundle layout is the loader's:
`<bundle>/kernels/*.metal`, `<bundle>/ggml-metal-impl.h`,
`<bundle>/ggml-common.h` (the last two resolve the `#include`s inside
`kernels/common.h`, `dequantize.h` and `quantize.h`).

The copies cannot drift quietly: `Tests/MindVaultASRTests/MetalKernelResourceTests.swift`
compares every file against `Vendored/` byte for byte and checks that every kind
in the loader's `GGML_METAL_LIBS` table has a source. A `default.metallib`
placed in the app bundle still takes precedence — the loader tries the bundle
before it reads the environment variable.

## Not vendored

- Models: downloaded, pinned by size + sha256 in `ModelRegistry`.
- The Android JNI wrapper: `tools/whisper-android/whisper_jni.cpp` is the
  contract this package reimplements; it is not compiled here.
